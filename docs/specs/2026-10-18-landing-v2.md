# cto-team landing page v2 (EN + VI) and README — Spec

Date: 2026-10-18 · CEO: nhattrung0911 · CTO: Claude (cto-team)
Replaces the direction of `2026-10-18-landing-readme.md` (CEO feedback: too long, no focus, too many benchmark
comparisons).

## Intent
Marketing and SEO for a public Claude Code plugin. A vibe coder (or the AI agent they ask to "find a GitHub skill
that levels up my coding quality") must see in a few seconds **what changes after installing it** and **why that
is better**, feature by feature. Benefits first, mechanics second, numbers only as small proof points.

## Goals
1. Landing page in English (`docs/index.html`) and Vietnamese (`docs/vi/index.html`), same design, with a visible
   EN | VI switch on both and `hreflang` alternates, deployed to https://cto-team-skill.pages.dev (`/` and `/vi/`).
2. Each page: a short hero (one-line promise + install command), a short animated diagram of one gate
   (workers → verifier → fixer → pass), then **one card per feature** in the list below, each card =
   feature name, "before → after" in one line each, and the benefit. Then 3 steps to start, then a footer.
   No long comparison tables, no benchmark chart section.
3. `README.md` (English) and `README.vi.md` (Vietnamese) follow the same structure: hero line + install, a feature
   table (Feature | Before | After with cto-team), a small Mermaid flow of one gate, 3-step usage, FAQ (3–4 lines),
   credits. Each links to the other language and to the landing page.
4. Good SEO: descriptive `<title>` and meta description per language, Open Graph tags, one `<h1>`, feature names as
   `<h2>/<h3>`, JSON-LD `SoftwareApplication`, keywords used naturally (Claude Code plugin, AI coding agent,
   multi-agent, subagents, code review, test quality, contract-first API, ripgrep, token cost, vibe coding).

## Features (the content; use these facts only)
| # | Feature | Before (typical agent use) | After (with cto-team) | Proof point (optional) |
|---|---|---|---|---|
| 1 | CTO plans once, then delivers gate by gate | One agent gets the whole plan and drifts | Workers get one brief each; the next gate starts only after this one passes | — |
| 2 | Contract-first API | Frontend and backend each guess the API | One contract file the CTO owns; workers may not edit it; the verifier checks the app against it | — |
| 3 | The CTO splits the team | You hand-assign agents; two agents edit the same file | You pick 1–5 Sonnet workers per gate; the CTO gives each disjoint files | — |
| 4 | Blind verifier on every gate | "Tests pass", says the agent that wrote them | A separate agent proves every acceptance criterion, runs the full suite, and breaks one line the tests must catch | — |
| 5 | No fake tests, no 500s | `assert True` slips through; huge input crashes | Fake tests fail the gate; every number gets an overflow test | v0.1 crashed on a 20-digit amount; fixed from v0.2 |
| 6 | Opus batch review | Bugs across features are found by users | Every 3–4 gates Opus reviews the batch | Found a real race condition the per-gate checks missed |
| 7 | Lean on tokens | Long-lived "member" agents grow huge | Every agent is one-shot and starts small; Sonnet does most of the work | 12k vs 42k start context; 0.9M vs 3.8M tokens per agent |
| 8 | ripgrep instead of grep | Slow recursive grep, noisy output | A hook points agents to ripgrep (faster, respects .gitignore) | — |
| 9 | Picks up after a reset | Context reset = redo or lost work | State lives in `docs/cto/`; delivery resumes from the last checkpoint | — |
| 10 | Report a non-coder can read | A long chat log | One HTML report: what works, how to try it, tech stack, architecture diagram, known gaps | — |
Quality reference (one line, optional, at most once per page): on a 10-task test app every version passed 14/14
hidden tests.

## Non-goals
- No change to skills/, agents/, hooks/, gate.js. No build tools or frameworks. No new dependencies.
- No deploy or push inside the delivery.

## Anti-goals
- Long tables or charts comparing benchmark runs; walls of text.
- Any claim not in the Features table (for example "SDD missed the race bug").
- English and Vietnamese pages saying different things.
- Broken on a phone or in dark mode; motion that cannot be paused or ignores `prefers-reduced-motion`.

## Constraints
- Page: self-contained HTML (inline CSS/JS), Google Fonts only; light + dark; works at 375px with no horizontal
  scroll; WCAG AA contrast; no body text under 12px; no thick one-sided accent borders on cards; uppercase only for
  short labels; at least 12px inner padding in bordered boxes.
- The draft `docs/landing-draft.html` is the visual starting point (blueprint grid, ink + amber, Bricolage
  Grotesque / IBM Plex). Its chart bars do not render (inline `span` with a width); drop the charts anyway.
- Vietnamese copy: natural Vietnamese for vibe coders, with technical terms kept in English where Vietnamese devs
  use them (gate, worker, verifier, test, contract, token).
- Install lines exactly: `/plugin marketplace add nhattrung0911/cto-team` and `/plugin install cto-team@cto-team`.
  Version 0.4.0. Repo https://github.com/nhattrung0911/cto-team. MIT; credit obra/superpowers.

## Decided (by the CEO)
- EN and VI, user can switch. Focus on features and benefits (rg, contract-first, team split, token savings,
  coding that follows the plan), for SEO and marketing. Deploy free on Cloudflare Pages as cto-team-skill.pages.dev.
