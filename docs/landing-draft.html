What the verifier checks at every gate

A gate passes on evidence only

Every criterion, by id

Each acceptance criterion in each brief is reported as G2-T1#3 with its own output line. A missing id fails the gate.

The full suite, green

The configured test command, its exit code and summary. Earlier gates' tests are the regression net.

One deliberate break

On money, auth or data gates the verifier breaks one line and the tests must catch it, then restores the file byte for byte.

No fake tests

assert True, tests of mocks and tests with no assertion count as missing tests.

Bad input never 500s

Every numeric input gets an overflow test; the verifier probes it itself.

No junk left behind

Scratch scripts, screenshots, logs and debug prints fail the gate. Real tests stay.

Matches the contract

Routes, field names and status codes are compared with the contract file.

Unproven means stop

A failure without evidence is never sent to fixers and never passes: the CTO rules on it.

Fit

When to use it, and when not

Good fit

New apps or features with 5+ tasks: web apps, APIs, CLIs, data scripts. Anything with money, logins or user data.

Not worth it

A one-file fix or a quick question. Each agent costs about 12k tokens to start, so tiny jobs are cheaper solo.

Needs

Claude Code with the Workflow tool (tested on 2.1.301). Optional: superpowers for planning, Playwright MCP for browser checks.
