Từng tính năng

Cài xong, có gì thay đổi

01

CTO lên plan một lần, giao việc theo từng gate

TrướcMột agent nhận cả plan và dần đi lệch hướng

SauMỗi worker nhận một brief riêng; gate kế tiếp chỉ bắt đầu khi gate này đã pass

Mỗi worker chỉ lo phần việc nhỏ của mình, và không gate nào chạy sớm.

02

Contract-first API

TrướcFrontend và backend mỗi bên tự đoán API

SauMột file contract do CTO giữ; worker không được sửa; verifier kiểm tra app theo contract đó

Hai phía cùng build theo một API, và verifier kiểm tra app theo đúng API đó.

03

CTO tự chia team

TrướcBạn tự giao việc cho từng agent; hai agent sửa cùng một file

SauBạn chọn 1–5 worker Sonnet cho mỗi gate; CTO giao cho mỗi người các file không trùng nhau

Bạn chỉ chọn quy mô team; CTO giữ các worker không đụng vào file của nhau.

04

Verifier độc lập ở mọi gate

Trước“test pass rồi”, do chính agent viết ra test nói

SauMột agent riêng chứng minh từng acceptance criterion, chạy full suite, và cố tình phá một dòng code mà test bắt buộc phải bắt được

Việc kiểm tra đến từ một agent không phải người viết code.

05

Không test giả, không lỗi 500

Trướcassert True lọt qua; input quá lớn làm app crash

SauTest giả làm gate fail; mọi con số đều có test overflow

Test giả bị chặn ngay ở gate, và mọi con số đều được test overflow.

v0.1 bị crash với số tiền 20 chữ số; đã sửa từ v0.2

06

Opus review theo đợt

TrướcLỗi nằm giữa các tính năng thì người dùng mới phát hiện

SauCứ 3–4 gate, Opus review cả đợt

Opus review nhiều gate cùng lúc, thay vì từng gate riêng lẻ.

Tìm ra một race condition thật mà các check theo từng gate bỏ sót

07

Tiết kiệm token

TrướcAgent “thành viên” sống lâu cứ phình to dần

SauMỗi agent chỉ nhận một task và bắt đầu nhỏ gọn; Sonnet làm phần lớn việc

Agent nhỏ, mỗi agent một task giúp chi phí token của bạn thấp.

Context lúc khởi động 12k thay vì 42k; 0.9M thay vì 3.8M token mỗi agent

08

ripgrep thay cho grep

Trướcgrep đệ quy chậm, kết quả lộn xộn

SauMột hook hướng agent dùng ripgrep (nhanh hơn, tôn trọng .gitignore)

Tìm kiếm nhanh hơn và bỏ qua những gì .gitignore loại trừ.

09

Làm tiếp sau khi reset

TrướcReset context = làm lại hoặc mất việc

SauTrạng thái nằm trong docs/cto/; việc giao được tiếp tục từ checkpoint gần nhất

Reset không làm bạn mất phần việc đã xong.

10

Báo cáo người không code cũng đọc được

TrướcMột đoạn chat dài

SauMột báo cáo HTML: cái gì chạy được, cách thử, tech stack, sơ đồ kiến trúc, những chỗ còn thiếu

Bạn đọc một trang thay vì lướt cả đoạn chat.

Chất lượng tham chiếu: trên một app test gồm 10 task, mọi version đều pass 14/14 hidden test.
