# Brief G1-T3: README.vi.md (Vietnamese)

## Goal
Create `README.vi.md`: a short, benefit-first Vietnamese README for vibe coders, same structure and facts as the
English README, written from the spec (do not wait for the English README; another worker writes it in parallel).

## Files you may touch
- Create: `README.vi.md`
Nothing else. Other workers own `README.md` and the landing pages.

## Interfaces
- Produces what `docs/contract/contract.md` lists under "Shared constants", "Feature names" (Vietnamese column)
  and "READMEs" (read-only for you; source of truth): `## Cài đặt`, `## Cách dùng`, the ten Vietnamese feature names
  in order in one feature table, a link to `README.md` labelled `English`, the link
  `https://cto-team-skill.pages.dev/vi/`, a ```mermaid block with a `flowchart`, the two install lines exactly.
- Content source: Features table in `docs/specs/2026-10-18-landing-v2.md`. The current `README.md` (English, old
  version) has the commands and settings facts you may translate.

## Global constraints
- Structure: `# cto-team` + one-line promise (natural Vietnamese, keywords like Claude Code plugin, AI coding
  agent, multi-agent, subagents, code review, vibe coding kept in English) + links line (landing page, English) →
  `## Cài đặt` (the two exact install lines in a code block; one line each on optional superpowers and Playwright
  MCP) → `## Thay đổi gì` table `| Tính năng | Trước đây | Với cto-team |`, ten rows from the spec, proof points in
  the last cell in parentheses only where the spec gives one → Mermaid `flowchart LR` of one gate (workers →
  verifier → fixer → pass) → `## Cách dùng` (3 steps: `/cto-team:plan`, `/clear`, `/cto-team:deliver <plan>`; you
  pick 1–5 workers per gate, default 3) → `## Hỏi đáp` (3–4 short Q&A: thay superpowers? chi phí? không có
  Playwright? bao nhiêu worker?) → short "Những gì xuất hiện trong project" (`docs/cto/` files, contract) →
  compact settings (the `CLAUDE_CODE_AUTO_COMPACT_WINDOW` / `CLAUDE_CODE_SUBAGENT_MODEL` JSON, tested with Claude
  Code 2.1.301) → credits (obra/superpowers) + license MIT.
- Natural Vietnamese for vibe coders; keep gate, worker, verifier, fixer, test, token, contract, plan, review,
  hook in English. Proof points translated faithfully: 5 "v0.1 crash với số tiền 20 chữ số; sửa từ v0.2"-style;
  6 a real race condition the per-gate checks missed; 7 "12k vs 42k context lúc khởi động; 0.9M vs 3.8M token mỗi
  agent". Say the same things as the spec, nothing more.
- Banned: any claim not in the Features table; the word "SDD"; benchmark tables or charts.
- Mermaid labels with spaces, diacritics or punctuation go in double quotes: `A["Workers (1–5)"]`. No parentheses,
  `|` or `:` outside quotes. Table cells must not contain a raw `|`.
- Version 0.4.0 appears once.

## Acceptance criteria
1. [Important] Content only from the Features table (plus translated settings facts); no banned claim; no
   benchmark tables or charts — check: read the file against the spec.
2. [Important] Renders on GitHub: valid Markdown table (header, separator, ten rows, same column count), Mermaid
   `flowchart` syntax with quoted labels — check: read the file.
3. [Important] Contains everything listed under Interfaces, ten Vietnamese names exactly as the contract, in
   order — check: read the file.
4. [Minor] Short: under ~120 lines — check: `wc -l README.vi.md`.
5. [Important] Says the same things as the spec's Features table, row by row (Before, After, proof point) —
   check: compare each row with the spec.

## Break-prone cases
- Unicode: all diacritics NFC (e.g. "độc lập", "Tiết kiệm"), file saved as UTF-8 without BOM.
- Mermaid: Vietnamese labels quoted; `flowchart LR` first line of the block.
- Relative link `README.md` (no leading slash).

## Commands
- Full suite (must stay green): `npm test`

## Out of scope
Landing pages, `README.md`, tests, the contract, any other file.
