# Brief G1-T1: Landing pages EN + VI

## Goal
Two benefit-first landing pages for the cto-team Claude Code plugin, same design: English `docs/index.html` and
Vietnamese `docs/vi/index.html`. A vibe coder sees in seconds what changes after installing it, feature by feature.

## Files you may touch
- Create: `docs/index.html`, `docs/vi/index.html`
- Delete: `docs/landing-draft.html` (read it first: it is your visual starting point)
Nothing else. Other workers own `README.md` and `README.vi.md`.

## Interfaces
- Produces exactly what `docs/contract/contract.md` lists under "Shared constants", "Feature names" and "Pages"
  (read-only for you; source of truth): `lang`, hreflang alternates incl. x-default, canonical, relative language
  switch (`vi/` and `../`), `#installCmd`, one `<h1>`, each feature name as the full text of an `<h2>`/`<h3>`,
  a `prefers-reduced-motion` rule, JSON-LD `SoftwareApplication`.
- Content source: the Features table in `docs/specs/2026-10-18-landing-v2.md` (read Intent, Goals, Features,
  Anti-goals, Constraints). Use those facts only.

## Global constraints
- Self-contained HTML: inline CSS and JS, Google Fonts only, no other external files, no build tools, no new deps.
- Visual system from the draft (tokens, blueprint grid, ink + amber, Bricolage Grotesque / IBM Plex Sans / Plex
  Mono, light + dark via `prefers-color-scheme` and `data-theme`). Take its tokens, not its sections. Drop all
  charts, the comparison section and the numbers section.
- Structure, in order: header (name, EN | VI switch, GitHub link) → hero (one-line promise, `#installCmd` with the
  two install lines + Copy button, GitHub link) → short animated gate diagram (workers → verifier → fixer → pass)
  with Pause/Play and Next buttons → ten feature cards → "Start in 3 steps" → footer (MIT, credit obra/superpowers
  with link, repo link, version 0.4.0).
- Feature card = name (h2/h3, exact), "Before" line, "After" line, one short benefit sentence that restates the
  After line's value (no new facts), and the proof point only where the spec gives one. Proof points exactly as the
  spec: 5 "v0.1 crashed on a 20-digit amount; fixed from v0.2"; 6 "Found a real race condition the per-gate checks
  missed"; 7 "12k vs 42k start context; 0.9M vs 3.8M tokens per agent". Optional quality line at most once per
  page: "on a 10-task test app every version passed 14/14 hidden tests".
- Banned: any claim not in the Features table (e.g. anything about SDD missing bugs); the word "SDD" anywhere;
  long tables; charts; walls of text.
- SEO head per language: descriptive `<title>` and meta description using keywords naturally (Claude Code plugin,
  AI coding agent, multi-agent, subagents, code review, test quality, contract-first API, ripgrep, token cost,
  vibe coding), canonical, Open Graph (`og:title`, `og:description`, `og:url`, `og:type`, `og:locale` en_US /
  vi_VN), JSON-LD `SoftwareApplication` (name, description, applicationCategory DeveloperApplication,
  operatingSystem "Windows, macOS, Linux", offers price 0, url, license MIT, softwareVersion 0.4.0). No feature
  names in title/meta/JSON-LD (contract order rule).
- Vietnamese page: faithful translation in natural Vietnamese for vibe coders; keep gate, worker, verifier, test,
  token, contract, plan, review in English. Same sections, same facts, same proof points. Use the exact Vietnamese
  feature names from the contract.
- Design rules: works at 375px and 320px with no horizontal scroll, cards one column on phones; WCAG AA contrast
  in light and dark; no text under 12px; no thick one-sided accent borders on cards (no `border-left: 3px+`
  accents); uppercase only on short labels; ≥12px inner padding in every bordered box.
- Fonts: load Google Fonts with Vietnamese support (`&subset` is automatic in css2; make sure the families you
  pick have a Vietnamese subset — Bricolage Grotesque, IBM Plex Sans, IBM Plex Mono do; if not, fall back to
  "Be Vietnam Pro").

## Acceptance criteria
1. [Important] Both pages are complete valid documents and open with no console errors — check: serve docs and
   load both pages in a browser, read the console.
2. [Important] Ten feature names exactly as in the contract, in order, on each page; every Before/After and proof
   point matches the spec's Features table; EN and VI say the same things — check: read both pages.
3. [Important] Language switch works both ways and hreflang alternates are present — check: click the switch on
   `http://localhost:8080/` and on `/vi/`; read the head.
4. [Important] At 375px: no horizontal page scroll on either page (`document.documentElement.scrollWidth <= 375`),
   cards stack to one column — check: browser at 375px.
5. [Important] WCAG AA contrast in light and dark, no text under 12px, no thick one-sided card borders, uppercase
   only on short labels, ≥12px padding in bordered boxes — check: computed styles in the browser.
6. [Important] The diagram animates, can be paused and stepped with keyboard and mouse (real `<button>`s with
   labels, `aria-live` status), and shows a static final state under `prefers-reduced-motion: reduce` — check:
   browser with reduced-motion emulation.
7. [Minor] No benchmark charts or comparison tables remain from the draft — check: read the source.

## Break-prone cases
- Dark theme by `prefers-color-scheme: dark` and by `data-theme="dark"` / `"light"` override → readable both.
- Clipboard refused or unavailable (`navigator.clipboard` undefined or rejects) → copy button falls back to
  selecting the install text and says so; never throws.
- 320px width → no horizontal scroll; long install lines wrap or scroll inside their own box only.
- Vietnamese diacritics ("Tiết kiệm token", "độc lập") render in the chosen fonts, not a fallback mix.
- JS disabled → all content (cards, steps, install lines) still visible; diagram shows its final state.

## Commands
- Serve: `python -m http.server 8080 --directory docs` (stop it before you return).
- Full suite (must stay green): `npm test`
