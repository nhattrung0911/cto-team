# Brief G2-T4: Consistency tests `tests/docs.test.mjs`

## Goal
A Node test file that keeps the two landing pages and two READMEs consistent with each other, with
`.claude-plugin/plugin.json`, and with the contract, so future edits cannot silently drift.

## Files you may touch
- Create: `tests/docs.test.mjs`
Nothing else. If a page or README does not match the contract, do not edit it: report it as a concern in your
result (name the file, the expected string, what is there).

## Interfaces
- Consumes (already exist, read-only): `docs/index.html`, `docs/vi/index.html`, `README.md`, `README.vi.md`,
  `.claude-plugin/plugin.json`, and `docs/contract/contract.md` (source of truth for every exact string: install
  lines, feature names EN/VI and their order rule, hreflang hrefs, language-switch hrefs `vi/` and `../`,
  `#installCmd`, README headings and link labels).
- Runner: `npm test` runs `node --test "tests/*.test.mjs"`; your file is picked up automatically.

## Global constraints
- `node:test` + `node:assert/strict` + `node:fs` / `node:path` / `node:url` only. No new dependencies, no network.
- Resolve paths from the test file (`fileURLToPath(new URL('..', import.meta.url))`), not from `process.cwd()`.
- Read the version from `plugin.json` at test time; never hard-code `0.4.0` as the expected value.
- Put the ten EN and ten VI feature names in arrays at the top of the file, copied exactly from the contract.
- Do not touch other tests, pages, READMEs, `skills/`, `agents/`, `hooks/`, `.claude-plugin/`, the contract.

## Tests to write (one `test()` each, clear names)
1. All four files contain both install lines exactly.
2. The `plugin.json` version appears in both pages and both READMEs.
3. The ten English names appear in order (first occurrence of k+1 after first occurrence of k) in
   `docs/index.html` and `README.md`; the ten Vietnamese names in order in `docs/vi/index.html` and `README.vi.md`.
   Also: each page has each name as the full text of an `<h2>` or `<h3>` (allow attributes on the tag).
4. Pages: `<html lang="en">` / `<html lang="vi">`; both hreflang alternates (en, vi) with the contract hrefs; the
   switch link to the other language (`href="vi/"` on EN, `href="../"` on VI); an element with `id="installCmd"`;
   `prefers-reduced-motion`; a `<script type="application/ld+json">` whose JSON parses and has
   `"@type": "SoftwareApplication"`; exactly one `<h1`; `docs/landing-draft.html` does not exist.
5. READMEs: `README.md` links `README.vi.md` with label `Tiếng Việt` and `https://cto-team-skill.pages.dev/`;
   `README.vi.md` links `README.md` with label `English` and `https://cto-team-skill.pages.dev/vi/`; headings
   `## Install` + `## Use` (EN) and `## Cài đặt` + `## Cách dùng` (VI); each has a ```mermaid block containing
   `flowchart`.
6. Banned claim: no file contains "SDD" in the same sentence as "miss" (case-insensitive; split sentences on
   `.`, `!`, `?`, or newline). Also no file contains the word `SDD` at all (the spec bans it from these pages).

## Acceptance criteria
1. [Important] The six tests exist, pass on the current files, and each can fail: for each test, name in your
   result the one-line change to a page/README/plugin.json that would make it fail; prove at least tests 1, 3 and
   6 fail by running them against a temporary modified copy (copy files to a temp dir and point a helper at it,
   or temporarily edit and restore — restore byte-for-byte and verify with `git diff --stat` that only
   `tests/docs.test.mjs` changed). — check: `node --test tests/docs.test.mjs`.
2. [Important] `npm test` green (the existing 92 tests plus yours) — check: `npm test`.

## Break-prone cases
- Unicode: Vietnamese names compared after `.normalize('NFC')` on both sides, so an NFD file still matches only if
  the text is the same; read files as UTF-8 and strip a leading BOM.
- Order check must fail when two names swap, and when one name is missing (report which).
- CRLF line endings: tests must pass with `\r\n` files (Windows checkout).
- Malformed JSON-LD → the test fails with a clear message, it does not crash the runner.

## Commands
- This task: `node --test tests/docs.test.mjs`
- Full suite (must stay green): `npm test`

## Out of scope
Editing pages, READMEs, other tests, or the contract. Leave no temp files behind.
